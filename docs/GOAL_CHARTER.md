# CityAtlas Goal Charter

Date: 2026-06-16

## Product And Audience

CityAtlas is a Univenture Studio project for local discovery and local-business growth. The first market is Vancouver.

Primary users:

- Locals who want curated routes, places, events, offers, and guides.
- Vancouver businesses that want better presentation, route placement, and founding partner visibility.
- The owner/operator who needs a local command console for proof, sales, readiness, and launch gates.

## Current State

CityAtlas has a public product surface, Vancouver discovery pages, City Missions, planner loop, business request flow, founder CRM, private Date Night preview, manual reply tracker, local AI Brain command engine, draft terms/privacy pages, and launch documentation.

## Why This Goal Matters

The business goal is not only to ship a pretty website. The goal is to create a ranking-ready Vancouver city-intelligence surface with enough useful routes, enough local-business density, and enough repeatable proof that CityAtlas can become both a discovery product and a business-visibility machine.

The repeatable part matters as much as Vancouver itself. CityAtlas should be able to reuse the same proof pattern across other launch cities and reuse the same outreach-prep discipline already developed in Roam Relaxation and Rooms without pretending that discovery research is the same thing as live outreach approval.

## Current Goal Outcome

Build CityAtlas from current repo truth into a ranking-ready Vancouver-first city-intelligence and business-visibility system: expand Vancouver business coverage, contact-path depth, and email density as far as safely possible, prepare reusable multi-city rollout infrastructure using the same target-city pattern as Roam Relaxation and Rooms, transplant and stage lead-capture plus outreach systems from those repos into CityAtlas, and keep paid discovery, scraping, and live outreach behind clear proof and approval gates.

## Definition Of Done

The current goal is done when:

1. CityAtlas has a durable Univenture project folder.
2. The crawlable Vancouver surface stays trust-first, answer-first, and protected from internal/operator copy leaks on the checked public pages.
3. The Vancouver business machine keeps honest deduped prospect truth, deeper email and contact-path coverage, a useful first-batch rehearsal packet, and clear donor-source boundaries.
4. The shared-city rollout machine remains reusable for the next launch cities instead of being a one-off Vancouver implementation.
5. The local app passes the current proof stack for growth, copy safety, structure, build, and readiness.
6. No live deploy, crawl-policy widening for protected routes, paid research run, outreach send, provider import, Stripe object, or real-business publication happened without explicit approval.

## Allowed Local Actions

- Code and docs edits inside this project.
- Local browser testing.
- Local builds, typechecks, and smoke checks.
- Local readiness reports.
- Local visual screenshots.
- Drafting Stripe product catalogs and terms.
- Drafting Vercel/Cloudflare cutover packets.
- Drafting business source/import packets.
- Refreshing donor-sync layers, widening local email/contact-path queues from approved donor packets, and rebuilding no-send outreach-prep packets.
- Preparing EXA research packets that remain discovery-only and unpaid until separately approved.

## Approval-Required Live Actions

- Vercel deploy, preview deploy, alias change, or rollback.
- Adding or changing a Vercel custom domain.
- Cloudflare DNS record creation, update, or deletion.
- Stripe product, price, payment link, subscription, invoice, coupon, tax, or portal changes.
- Supabase project creation, schema migration, or production data write.
- Real provider import or paid Exa/provider spend.
- Outreach, email, DM, CRM sync, or customer-facing send.
- Public business page publication or widening public real-business claims beyond the approved source-backed pattern.
- Widening crawl/index access to protected routes or changing the approved robots/indexing posture.
- Domain purchase or brand-lock decision.

## Off-Limits Until Approved

- Live payment acceptance.
- Automated outreach.
- Paid EXA or scraping runs.
- Real business claims from scraped/imported data.
- Public unauthenticated admin CRM.
- Treating draft terms/privacy as legal clearance.
- Treating the name as final trademark clearance.

## Proof Required Before Stopping

- `npm run typecheck`
- `npm run growth:verify`
- `npm run seo:copy:proof`
- `npm run seo:proof:stack`
- `npm run build`
- `npm run readiness`
- Local route checks for `/`, `/admin`, `/for-businesses/pricing`, `/terms`, `/privacy`, and `/private-preview/date-night`
- Desktop and mobile visual review when visible UI changes
- Updated readiness percentages and next approval packet
