# CityAtlas Content Release Checklist

Use this before any guide, city page, mission page, landing page, or business-facing editorial asset is treated as ready.

## Decision

- `Ship`
- `Revise`
- `Kill`
- `Rebuild`

## Hard Stop Questions

1. Is the audience of one clear?
2. Does the piece answer a real Vancouver planning question?
3. Is the opening specific, useful, and non-generic?
4. Does the draft avoid fake "best of" or unsupported authority language?
5. Are all business, event, pricing, safety, and availability claims either reviewed or clearly marked draft/demo?
6. If the page names a real business or venue, are the official source, checked date, and correction path visible?
7. Does the body provide real route logic, decision help, or first-hand-style utility instead of fluff?
8. Does the page link to the right next step: guide, mission, planner, or business action?
9. Would the wrong audience be pulled in by this piece?
10. If this were quoted by an AI answer engine, would the summary still be honest?
11. Does the draft strengthen trust more than it chases traffic?

## Minimum Release Gates

- Answer-first opening is present
- One query class is explicit
- One CTA is explicit
- Internal links are present
- CityAtlas hook score passes
- No unsupported claims
- Demo/draft status is clear where needed
- If a real venue is named, the official source, checked date, and correction path are visible

## Default Decision Rules

- `Ship` only when the page is useful, specific, honest, and aligned
- `Revise` when the page is promising but still too generic or weakly structured
- `Kill` when the query is wrong, the audience is wrong, or the trust risk is too high
- `Rebuild` when the underlying angle is too vague to save with line edits
