# CityAtlas Hook Intelligence

This folder defines how CityAtlas openings should work before a guide or source-backed wedge is allowed into the queue.

The goal is not generic travel click-through. The goal is a trustworthy, answer-first opening that makes a Vancouver planning moment feel easier to solve.

## What CityAtlas Hooks Must Do

- name the Vancouver moment quickly
- call in the right audience
- promise a real route, choice, or planning payoff
- avoid fake local authority, hype, or "best of" language
- fit the actual body copy and CTA

## Read Order

1. `HOOK_RUBRIC.md`
2. `../seo-aeo-geo/ENTITY_AND_QUERY_MAP.md`
3. `../content-quality-gate/RELEASE_CHECKLIST.md`

## Default Workflow

1. Pick one query class from `ENTITY_AND_QUERY_MAP.md`.
2. Write three opening angles for the same page.
3. Score each angle with `HOOK_RUBRIC.md`.
4. Keep only hooks that pass the trust-honesty bar.
5. Carry the winning hook into the full draft, then run the content gate.

## Strong CityAtlas Hook Shapes

- choose the right Vancouver start before the day gets overbuilt
- build one confident route without crossing the city all day
- give a guest one good Vancouver introduction without trying to prove everything
- rescue a rainy, low-energy, or time-limited city moment fast
- choose by mood, pace, or route shape instead of generic listicle volume

## Hooks To Reject

- "best Vancouver..."
- "top hidden gems..."
- "locals don't want you to know..."
- "discover Vancouver like never before..."
- any line that sounds like it could belong to any travel blog
